# 昵称游客双人对战

2026-10-08 已部署腾讯云硅谷试玩节点：http://43.135.186.21:8088/ 。发布版本 `20261008-guest-v3`，独立运行时 Node.js 22.23.3、WebSocket 依赖 ws 8.21.0。

本轮加入服务器权威判定的双人对战。单机存档、装备图鉴、阵营特性和原有规则保持独立。

## 玩家流程

首次进入输入昵称。选择战场、胜利规则和阵营，点击「联网对战」创建房间，把六位房间码发给朋友。双方准备完成后由房主开战，每位玩家还可在准备前调整阵营。

游客可同名，服务器以随机身份编号区分，不等于实名认证或微信唯一账号。身份凭据在 HttpOnly、SameSite Cookie 中，战绩保存在服务器 SQLite 数据库。本机荣誉不因联机胜负改变。清理 Cookie 或更换浏览器会得到新的游客身份。

对战不能单方面暂停或保存成单机存档。刷新后自动重连，断线期间双方共同暂停，前三次每次最多 60 秒，之后每次最多 10 秒；单方超时判负，双方超时平局。主动退出判负。服务器重启会取消尚未结束的战局，不补记胜负；已结算战绩保留。

## 架构

- 浏览器：Three.js 战场、局部插值、选择和镜头操作，不判定伤害或资金。
- 服务端：Node.js 22 最新维护版本、WebSocket、同一套 Game 规则，20Hz 模拟、10Hz 视野快照。
- 公平性：双方同资源规则，无电脑 AI；只发送己方实体、当前可见敌军和已探明建筑记忆，迷雾按两位编码压缩。
- 校验：实体归属、坐标、生产前置、已建成建筑、指令序号、频率和报文长度；客户端不能提交胜负或修改资金。
- 容量：初版最多 4 场同时对战、20 个房间，每方生产队列与现有单位合计上限 120。尚未做压测，不承诺大规模并发；需结合硅谷延迟实测扩容。
- 微信：本轮未启用，后续以审核通过的网站应用、HTTPS 域名和服务端 OAuth 绑定身份。没有客户端 AppSecret 或虚假扫码入口。

## 本地运行

需要 Node.js 22.16 及以上，建议使用最新 Node.js 22 维护版本。

```sh
npm ci
npm run build
npm run server
```

默认 http://127.0.0.1:4180/ 。开发时另运行 Vite，其 `/api` 和 `/battle-socket` 代理到 4180。已有旧 Vite 进程首次新增配置时需要重启才能读取代理设置。

## 独立部署

`scripts/deploy-online.sh` 校验发布包 SHA256，安装独立 Node 运行时，创建低权限账户并用 systemd 托管。目录 `/opt/great-powers/current` 原子切换，健康检查失败恢复旧目录。数据库位于 `/var/lib/great-powers`，更新不覆盖。

腾讯云硅谷实例现有 80、443 服务不改动，游戏使用 TCP 8088。仅添加这一条云防火墙规则，不放通所有端口。当前为 IP HTTP 试玩，正式账号与排名前必须配置域名及 HTTPS；HTTP 游客会话不提供传输加密，不应承担付费或个人敏感信息。

运维命令：

```sh
systemctl status great-powers
journalctl -u great-powers -n 80 --no-pager
curl http://127.0.0.1:8088/api/health
```

首次部署前后备份数据库需要短暂停服或使用 SQLite 在线备份，不能只复制正在写入的 WAL 主文件。升级维护前应通知玩家，避免正在进行的战局被取消。
