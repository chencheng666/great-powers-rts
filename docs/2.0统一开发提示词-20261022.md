# 《大国崛起》2.0 统一开发提示词

以下正文可直接复制给开发助手。它授权在工作区实施和测试，不自动授权生产部署、GitHub推送、付费生成或公众号发布。

---

请继续完善我的原创浏览器三维 RTS《大国崛起》，按照 2.0「山海防线」方向分阶段开发。范围包含海峡风云、列岛守望、深蓝生命线、山口防线、归航行动、钢铁走廊、战略警戒、明日·月海基地，以及远东·寒境守望，共九大战区，不得遗漏。

不要只给方案，也不要一次铺开大量半成品。顺序为深蓝生命线 → 列岛守望 → 远东·寒境守望 → 海峡风云与山口防线 → 归航行动与钢铁走廊 → 战略警戒与明日·月海基地。每阶段必须可玩、可测试、有实机截图，再推进下一阶段；后续战区不因排期较后就从2.0范围中删除。

现有运输收入、补给光环、舰艇返港、登陆运输、工程师接管、四关挑战、复盘、存档和联机应优先复用。重点检查 `src/logistics-economy.js` 的挑战模式跳过逻辑、双边货运入口及矩形水域假设，扩展时保持旧关卡和旧存档行为。

## 二、产品主题

主题是「守护山海，走向深蓝」：侦察、运输、护航、维修、登陆、占领和协同形成策略，不是单纯增加更大武器。保留当前正式游戏名，「山海防线」作为2.0主题，不擅自改仓库、域名或图标。

采用原创架空地图与战役，参考真实地貌与公开装备风格，不编写现实攻击方案，不把历史疆域变成当代领土索取清单。远东是寒区边境与滨海作战环境，不按真实城市或设施坐标设计攻击目标。未来月面与现代战场分开，现实资料、游戏参数和科幻设定明确区分。

## 三、第一优先：深蓝生命线

开发可通关的远海运输护航任务，再扩展对称遭遇战。包含双方起始港、至少两条可选航道、中转岛与清晰的战略节点，不靠无限放大地图拉长空驶时间。

资源由货船实际抵港卸货后发放，空运承担低效率应急保障，保留有限基础恢复收入与油井；普通战区不依赖挖矿，月面保持现有逻辑。载兵运输与经济货运分离，多港共享配额，避免重复结算、反复卸货和造港刷钱。

实现清晰的货运任务状态、目的港选择、限额补发和暂停恢复。港口提供独立卸货、维修与登陆位置，有限泊位和外海排队；舰艇与潜艇可修复和补弹，消耗合理资源。处理港口被毁/易主、断电、资金不足、取消、拥堵及替代港，不传送、不无限回血、不追船抖动。

让侦察、护航、截击、绕行与整备都能影响胜负。AI受同等预算和视野约束，不能靠迷雾透视埋伏。主目标可见、可定位，首班货船损失后有恢复机会。

## 四、第二优先：列岛守望

基于上一阶段物流体系制作无陆桥列岛战场。串联侦察、装载、海运、合法卸载、工程师接管、驻守、恢复供电、港口接驳和下一段前哨。

各岛有清晰资源与战略价值，登陆区视觉和碰撞一致。卸载逐个检查有效落点，不重叠生成、不穿山；失败可说明和取消。争夺、连续控制与积分可见，敌我同时在场不抖动归属。占领后仍需供电及运输才能发展，设施失守可夺回、破坏可恢复，不软锁任务。单机脚本与公平对战规则分离。

## 五、第三优先：远东·寒境守望

制作原创寒区山地与滨海地图，包含针叶林、山口、河流、桥梁、货场和港区。不是现有平地贴白色纹理，也不是现实领土征服地图。

先做「北境归航」：保护运输编队经过补给节点、修复中转站并抵达港区，提供短而暴露与长而安全的路线取舍。后续再做山口接力防御。铁路首版仅为场景与节点，不假称完成铁路物流。天气先做视觉，不加无提示随机惩罚。

## 六、其余六个战区全部纳入开发

| 战区 | 必须实现的区别与完成标准 |
| --- | --- |
| 海峡风云 | 双岸、大岛、外岛与港口；立足、接通运输、守住前哨、阶段推进。与列岛的并行积分争夺区分，阶段失守可恢复，存读档不跳阶段 |
| 山口防线 | 山地河谷、桥梁、高差与侧路；固定编队、有限增援、预警压力和撤退整备接防。与远东地域运输战役区分，不把未实现高地机制写成加成 |
| 归航行动 | 海港、居民区与集结点；保护、分批装载和撤离，运输能力比击毁数量重要。撤离只结算一次，民用目标不提供攻击奖励；首版单机友方AI，合作另验真正队伍和共享任务协议 |
| 钢铁走廊 | 工业区、铁路节点、能源设施；占领、修复、供电和物流共同决定有限产出。破坏降低后续收益但可恢复，不能反复易主刷钱；首版不冒充完整铁路调度 |
| 战略警戒 | 精修既有大地图及战略设施，加入预警、分散保障、设施保护与反制任务。复用已有威慑规则，核武器默认关闭、联网全员确认，纯常规也可通关，不新增必胜按钮 |
| 明日·月海基地 | 独立未来篇，陨坑、高差、太阳能区与矿区；机器人采矿、电力储能、通信中继、整备和断线恢复。弹药型装备仍需补弹，不把月面机械直接替换所有现代地图单位 |

九战区各有至少一张可玩地图和一项独特任务循环、清晰胜负、重试、存档、复盘和实机截图。可复用战略/月表等已有地图深化内容，不以九张换皮图凑数。共同复用运输、泊位、占领和任务机制，不复制九套规则。

维护九战区进度矩阵，分别标注未开始、开发中、待验收或已通过，以及实际支持的单机、双人、六方、合作模式。阶段候选版本只展示已通过内容；正式2.0目标是九战区首版达标，缩减范围须用户确认。完整连续战役、所有战区六方、合作等未达标功能如实列待办，不能将六方自由混战称为合作。

## 七、美术与性能一起做

优先精修集装箱船、登陆舰、港口，再做护航舰与寒区补给站。要求真实体块、合理比例、金属/橡胶/玻璃/混凝土材质差异、贴图细节、接地阴影、吃水尾流和可读轮廓；地面不过白、不全黑，敌我单位不融进背景。

现代建筑入口、生产方向和预览一致，检查非房主及重排席位。海岸、浅滩、码头和单位通行一致。共享材质、分级细节与视口预算，不以增加零件数代替精美。不未经授权接入付费建模服务，不引入来源不明素材。

随后分阶段精修海峡纵深、山口桥谷、救援集结区、工业管线能源设施、战略预警设备，以及月面机器人和能源网络。每张图必须有自身地形语言与关键模型，不仅换色；没有港口的地图不必硬塞港口近景，展示真实核心交互即可。

每阶段给实际引擎的全景、正常指挥距离和重点模型近景，不用概念图冒充实机。主要验收桌面端，记录120/240单位相同场景性能与明确硬件条件，不用后台节流数据承诺帧率。

## 八、必须守住的规则

运输、维修、补弹、占领与资源均由模拟核心决定，联机时服务端权威。存档及重连覆盖任务中间状态，不能复制货物、重复收入、丢载员或遗留泊位。保留旧荣誉、挑战成绩及备份恢复。

六方单独验证，不能把双边入口和相对敌我规则直接套用六席；未通过的模式明确限制。保护迷雾和越权校验，不顺带宣称完成3v3、微信登录、排位或全部硬件兼容。

复盘新增运输损失、运抵价值、整备支出、登陆成败和占领变化。胜利评价考虑任务、损失与效率，徽章不提供战斗属性优势。

## 九、执行与交付

先简要说明代码核查结果与第一阶段范围，然后实施深蓝最小闭环。按风险补自动测试并真实试玩通关，不依靠调试接口改任务状态。覆盖重复结算、零钱、断电、拥堵、易主、装卸读档、争夺、越权和视野泄露；回归已有模式。

后续各战区补充阶段回退、有限增援与波次读档、撤离去重、保护目标权限、工业产出、能源断连恢复和关闭核规则测试。九战区未全部验收前不直接标正式2.0，也不把未开发地图写入已完成功能。

每阶段交付改动说明、测试结果、实机截图、性能条件和已知问题。启动本地预览并提供地址；清楚区分已验证、待验证和未开发。完成一阶段再进入下一阶段，不能只搭菜单和模型就结束。
