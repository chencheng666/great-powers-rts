# 动作、联机与策略优化

发布状态：纳入 GitHub v0.8.0 源码与离线试玩包；2026-10-09 已同步公网网页及对战服务，见[服务器发布验收](服务器发布验收-20261009.md)。

## 本轮改动

- 普通人物的腰部瞄准与双腿分离，上身转角限制约 63 度，身体随瞄准转向；步枪手的持枪手臂与枪械共同后坐。月表机器人保持现有专用机体，不宣称完成机器人全身骨骼动画。
- 主战坦克的炮管与炮塔分离，炮塔不再整体平移。履带板采用两侧实例化网格，依据实际行驶距离循环，倒车反向、暂停停转。拉近到 140% 后显示循环履带细节，远景保留基础带体和轮组。
- 近景保留细分材质；低于 170% 的普通人物按关节合批，从最多 16 个网格降到 6 个，保留腰、持枪、腿和膝动作。玻璃增强清漆反射，金属增强金属性，橡胶保持消光。
- 联机收到快照后保留当前呈现位置，逐帧插值位置、车体朝向和炮塔角度，跨正负 π 时走短路径；重连大跳变或登载不硬插值。后坐以本地渲染时间推进，不等待下一次服务器快照；战斗判定仍完全在服务端。
- AI 仅根据可见、可探测的威胁选择防空、激光反无人机、反装甲火力、护卫舰、潜艇与战斗机。在造队列计入配额，科技、生产设施、阵营、地图和费用限制不变。
- AI 作战单位低于 32% 生命或不多于 25% 弹药时，尝试撤回现有设施整备。载客运输与已经整备的单位不覆盖命令；维修与补弹沿用供电、资金和脱离交火条件，不免费回血。
- 战后复盘提供击毁、战损、建筑、有效伤害、生产、修复、整备、后勤和据点控制十三项指标，以及最近八次关键损失。有效伤害不计溢出量；初始部队不计新造，卖出／回收不计战斗损失。控制时间为各设施占领时长累加。
- 新存档保存统计；旧存档缺少的战损／伤害／整备历史不补造，已有后勤累计仍保留。复盘不是录像回放，联机统计仅在结束后公开，并按每位玩家的我方／对手重排。
- 行军避让预先计算附近单位的可见性和半径，剔除不可能影响候选方向的远邻，减少重复平方根和可见性查询；碰撞、局部绕行、双方约束不变。

## 实际验收

`npm test`：267／267 通过。`npm run build`：成功，仍有原有大包体提示。`git diff --check`：通过。

两个真实浏览器页面通过六位房间码创建、加入、准备和开战，运行同一场服务器权威对战，分别从两个席位下达行军命令。每位采样 75 个渲染帧，覆盖约 27 次不同战局快照；两边各有 48 个同快照帧观察到炮管持续回弹，炮塔整体平移为零，人物上身转角未超过限制。实际认输指令触发服务端结算，两个页面均显示十三项复盘，第二席位数据与第一席位正确对调。页面无运行异常，结算按钮在桌面视口可访问。

本地压力场景包含两军坦克／步兵混编、移动、避让、枪炮交战、双方战争迷雾已揭开；测试机 WebGL 报告 Apple M1 Pro／ANGLE Metal，画布 1512×900。不是跨硬件帧率承诺，也不是竞技平衡验收。

| 单位数 | 画质 | 模拟 CPU 中位数 | 绘制提交 CPU 中位数 |
| --- | --- | --- | --- |
| 60 | 高 | 2.4 ms | 8.0 ms |
| 120 | 高 | 7.3 ms | 15.5 ms |
| 240 | 高 | 30.3 ms | 32.3 ms |
| 240 | 标准 | 30.2 ms | 20.2 ms |

所有样本均确认真实交战伤害、非空画布、WebGL 错误为零。早期 240 单位样本的模拟约 68–70 ms，优化后约 30 ms；这些短样本包含不同运行时序，不能当作严格同帧对照或普遍性能提升比例。60／120 单位样本帧间隔中位数约 33 ms；后段出现约一秒的浏览器帧调度，原因尚未单独确认，不能从中推导普通窗口连续游戏帧率。240 单位密集对冲还未达到稳定 60 帧验收目标，后续重点仍是单位合批、阴影绘制和碰撞分离性能。

验收图片和原始 JSON 保存在本地 `releases/animation-tactics-qa/`，不自动发布含测试身份的文件：双客户端战斗、双方联网复盘、单机复盘、240 单位两档画质，以及逐帧位置／炮管／上身／履带状态。

## 复现

先启动本地 Vite 的 4173 和 4182 端口，再单独运行 `node scripts/animation-qa-server.mjs`。该服务使用临时数据库，只监听本机，终端输入 `fixture` 注入测试部队；不增加公网调试接口。两个客户端分别访问 `http://127.0.0.1:4173/` 与 `http://localhost:4182/`，以不同主机名隔离游客身份。

`scripts/verify-dual-animation-browser.js` 的默认阶段创建双客户端对局；输入 `fixture` 后以 `DUAL_PHASE=capture` 执行采样和真实认输结算。需要已有活动的 ego-browser TaskSpace 及 p1／p2 页面，不自动创建任务空间。

`node scripts/run-browser-check.mjs army-performance 当前任务空间编号` 使用 p1 运行军团压力场景。该脚本会建立与结束测试单机局并写入该测试来源的荣誉／自动存档，必须使用专用测试来源，勿复用玩家正式存档的浏览器来源。

## 后续边界

目前为分组关节动画，不是动作捕捉或完整 IK。履带模板可复用，但不同装备还需逐个检查；没有声称所有人物与所有车辆都完成电影级写实动画。联机本轮为本地双客户端实测，公网高延迟／丢包仍需专项测试。上线时必须同步更新网页和权威服务端，不能只部署静态包。
