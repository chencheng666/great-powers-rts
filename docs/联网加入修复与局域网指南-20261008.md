# 联网加入修复与局域网指南

## 反馈与定位

2026-10-08 根据玩家反馈排查输入房间号后无法进入的问题，同时完善局域网联机入口。此公开说明仅保留技术问题与处理结果，不发布私信内容或用户标识。

在公网旧版中，用正确六位房间码实测：回车不提交，点击加入按钮可以进入。原因是加入表单直接禁止提交，加入按钮只处理点击。此外，首次连接时按钮尚未禁用，连接完成前点击可能没有发出有效指令；缺少直接可见的大厅错误提示。

这些是实际复现或代码确认的问题，但不能断言 CAI 的具体操作一定只有这一个原因。如果更新后仍失败，需要继续核对房间码、房间是否已满或开战、两位玩家是否访问同一个服务，以及是否误用同一浏览器身份。

## 本轮修复

- 回车和点击加入都通过同一个提交入口执行，不重复提交。
- 房间码校验支持全角数字、复制时的空格；不完整号码和夹杂字符直接提示。
- 初次连接时禁用建房与加入按钮，等待服务端欢迎消息确认身份和已有房间后才启用。
- 加入失败、服务不可达、版本不一致等错误直接显示在大厅中，不隐藏在遮罩后的通知里。
- 已在房间中的玩家不能直接跳入另一个房间。
- 同一浏览器的另一窗口占用连接时给出说明，不将两个标签页当成两位玩家。
- 离线 HTML 明确提示不能直接联机；普通静态服务与真实对战服务加以区分。
- 会话请求和连接握手设有超时，欢迎消息前断线及时失败。

房间码是某一台对战服务内的六位编号，并非跨服务器通用。双方准备后仍由房主开始战斗。房间目前只支持两位玩家，未改为三人对战或微信小程序。

## 浏览器局域网联机

可以用浏览器实现，不要求每位玩家安装客户端。一台电脑运行 Node.js 对战服务，其他电脑通过浏览器访问它。

房主电脑需要完整源码、Node.js 22.16 及以上版本和已安装依赖。首次安装依赖需要网络；构建产物和依赖准备好后，局域网对战不需要外部公网服务。当前离线试玩 ZIP 仅含单机 HTML，不包含 Node.js 对战服务，不能直接用它建局域网房间。

在项目目录执行：

```sh
npm ci
npm run build
npm run server:lan
```

启动后终端显示局域网网址，例如：

```text
http://192.168.0.207:4180/
```

朋友使用自己电脑的浏览器打开终端显示的网址，房主创建房间，朋友输入六位房间码加入。只需房主运行服务；其他电脑不需要安装 Node.js。不要让朋友打开 `localhost`，那指向朋友自己的电脑。不同操作系统的浏览器可以连接同一个房间。

有多张网卡或 VPN 时，终端可能列出多个地址，选择与朋友处于同一局域网的地址。只在可信本地网络放行对应 TCP 端口，不建议为局域网试玩把端口暴露到公网。访客 Wi-Fi、无线客户端隔离或主机防火墙可能阻止设备互相访问。

默认端口是 4180；macOS/Linux 更换端口示例：

```sh
PORT=4186 npm run server:lan
```

Windows PowerShell：

```powershell
$env:PORT = "4186"
npm run server:lan
```

房间保存在服务内存，关闭服务会中止未结束战局。已结算游客战绩存于数据目录中，不要随意删除它。当前游客服务不提供加密传输或实名认证，不应传递敏感资料。
