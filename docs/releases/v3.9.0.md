# 3.9.0：前线增援与联合作战

## 前线指挥

基地精简为指挥中心、后勤仓库、带雷达的空军基地、海军港口，另保留防御炮塔。供电合并到指挥中心与仓库；研发条件、情报来源、陆军整补和采购接收职责一起迁移，不需要重建工厂与实验室。

机场与港口承担接收、维修和补弹。订单先预留编制，飞机从地图边缘飞来进场，舰船从外海驶入，舰载机直接转场航母。机场六机位、港口六泊位，航母沿用24机编制与6机同时出动；在途与出击均占位，取消、损失与转场按同一规则处理。增援交接前不能提前指挥，基地损失后尝试改降或撤出。

地面增援由可拦截的运输航班送至本方仓库附近安全区域。重车着陆卸载，轻装备与人员以伞降表现交付；运输机一次载一辆重车或三辆轻车，人员每人一格。敌方击落交付航班时，不会再生成载荷。常规运输装卸仍需安全陆地，不提供任意敌后落点。

## 电脑与协同

电脑根据已侦察的威胁调整部队，并在侦察、集结、推进与防守之间切换。预留整补预算，正常支付增援成本，攒钱调入运输与舰队关键装备。运输机装卸点避开建筑，制空机与舰艇组织护航；返场、装载、接管和紧急规避命令不会被普通推进覆盖。补给与防空靠近陆军编队，相同目标保留已有路径。

## 程序画面与性能

新增程序化仓库、机场旋转雷达、六个突堤泊位及伞降表现；南部港口朝向按实际外海接近方向确定。继续沿用雪岭、河谷、森林、湿地、草地、沙地与海湾，以及区域雨雪和环境声音。

每步建立实体与战斗目标索引，保留同分目标顺序；错开陆军寻路并限制同一步重算数量。登陆装载改用近岸查询和有上限的地形缓存，避免每名乘员每帧扫描整张地图。机场贴地几何与泊位资源随实体移除释放，共享模板继续复用。本地存档的迷雾采用位编码，减少六方存档占用；读取恢复完整状态，旧JSON和导出格式保留。
