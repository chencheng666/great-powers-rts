# 挑战档案、兵种复盘与精模稳定

2026-10-20，本地开发续作。延续两关挑战与事件时间线，不改正式版本号，未推送 GitHub、更新下载包或部署服务器。

## 挑战成绩

首页“战术挑战”现在同时显示每关最佳星级、最快通关、完成次数和最近挑战。星级与最快时间各自记最佳，不保证来自同一场。失败不会降低已有最佳成绩，也不会扣普通荣誉。

- 成绩只来自已结束的本地挑战，同一战局编号只累计一次；从相同存档再次结算不会刷尝试和通关次数，重新开始才是一场新挑战。
- 成绩保存在同一浏览器、同一网站来源下。不是服务器排行榜，也没有跨设备自动同步；更换浏览器或地址前可导出备份。
- 导出为独立挑战成绩 JSON，不与战局存档、荣誉档案混用。导入先预览新增数量，再按战局编号合并；重复文件不多算、较差结果不覆盖最佳，同场内容冲突则拒绝合并。
- 存储失败时仍可查看复盘，并显示重试保存。坏档不会被自动重置为空档。最多保存 5000 场完整结算，达到上限会明确提示，不静默丢弃历史。
- 旧版没有保存过的挑战成绩不凭空补录。本机档案不是防作弊、排位或账号身份凭证。

主要实现：`src/challenge-profile.js`，UI 沿用现有主界面与结算弹窗；普通荣誉和游戏存档格式独立保留。

## 兵种复盘

战后新增“兵种战损与估算补充成本”：按装备类别显示双方损失数量与补充造价，完整累计不依赖最多 96 条的事件时间线。

估价使用损失方自己的阵营生产价格，例如东亚攻击无人机的折扣，而非我方价格；它是补充同类装备的参考，不是该局实际支出或严格战损交换比。自动货运、临时蜂群按零补充造价计，建筑仍列在原有建筑损失统计中。

旧存档从本次读档时间起记录兵种明细，并明确提示历史缺失，不从已截断事件中伪造完整数据。联机进行中不下发复盘；结束后，兵种汇总和其他指标一样按席位重排。

同时修复六席旧存档完全没有战斗统计时只恢复两席数据、导致再次保存校验失败的问题。

## 精模与性能

- 人物精模切换不再只用一个缩放阈值：精模与简模、履带细节、军团人数预算均使用不同的进入／退出条件，减少临界值波动造成的反复显隐。
- 预算边缘优先保留已展示精模的相近人物；新选中的人物仍可优先获得精细度。各关节和正常行军逻辑不变。
- 按实际画面范围分配细节名额，视口外保留一定模型余量；远处部队不占当前镜头的精模名额，视口外履带不单独动画。

高画质、1.8 倍镜头的混合交战样本：120 单位 3757 次绘制／3198952 个三角形，240 单位 6565 次绘制／4928334 个三角形。与前一批预算相近，主要收益是切换稳定性，不是新增 FPS 承诺。帧时间仍有约一秒节流采样，固定硬件前台长测、显存和长局尚未完成。原始记录：`releases/challenge-review-20261020/army-stable.json`。

这轮没有宣称重做全部武器模型；人物、建筑、航空器的进一步精修仍在 2.0 清单内。

- 410 项自动测试通过；构建通过，入口包体积提示仍在。新增 16 项测试覆盖档案校验／容量／去重／合并／存储失败、兵种成本／旧档／六席重排，以及精模迟滞。
- 浏览器正常护航通关后保存成绩，刷新仍可读取；重复结算、原生文件下载、导入新增和重复导入、错误文件拒绝、模拟空间不足及同一战局重试保存均通过。
- 验收确认普通荣誉、手动与自动存档未被改写；临时测试成绩在结束后恢复到测试前状态。没有清除 Cookie、登录态或其他站点数据。
- 1600×1000、1280×800 档案与复盘界面无横向溢出；页面没有未捕获错误。
- 170 人场景实测缩放序列 `1.8 → 1.68 → 1.72 → 1.6 → 1.57 → 1.7 → 1.8`，精模数量为 `12 → 12 → 12 → 12 → 0 → 0 → 12`，与实际模型显隐一致；原生点击选人、右键行军后位移大于 6，选中人物保留精模。
- 桌面及窄屏画布非空、图形错误为 0。窄屏只做基础回归，不新增手机端设计优先级。没有新增 Windows、麒麟／UOS 真机或双客户端视觉验收。
