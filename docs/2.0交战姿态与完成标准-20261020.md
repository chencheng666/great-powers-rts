# 2.0 交战姿态与完成标准

日期：2026-10-20。当前仍是 1.1.0 基础上的本地开发增量，未标正式 2.0，未推送、重新打包或部署。

## 距离 2.0 的实际差距

不按代码数量估算百分比，按可验收的体验划分：

| 必须补齐 | 当前基础 | 仍需交付 |
| --- | --- | --- |
| 画面质量 | 三维场景、分材质、动作、履带、人物精模预算 | 陆战／海战／月表／战略四类实机标杆；重点机型结构、近景贴图、光照与地面过渡统一 |
| 性能与兼容 | 视口精模预算、迟滞切换、120／240 单位绘制样本 | 约定硬件上的连续帧时间、显存、加载时间与带宽记录；Windows Edge、麒麟／UOS 实机 |
| 联机可靠性 | 权威判定、双人房间、实验六方、重连、情报隔离 | 新装备双客户端画面、六方长局、丢包与重连恢复、观战及容量压测 |
| 战术与平衡 | 五阵营、有限补给、电子战、核威慑反制、连续航点 | 真人镜像与交叉对局数据；资源节奏、反制窗口、复杂队列与堵塞长局复测 |
| 单机内容与成长 | 两关挑战、成绩备份、事件及兵种战损复盘 | 登陆／侦察／截击关卡、难度阶梯、科技分支；完整回放与虚构肩章尚未实现 |

科技分支、可驻军建筑、烟幕和桥梁互动等还没有实现。3v3、匹配排位、微信身份、月面能源网络与更多空天装备属于进一步扩展，不把游客昵称或六方自由对战等同于正式平台。

## 本轮新增：陆军交战姿态

| 姿态 | 行为 | 代价与边界 |
| --- | --- | --- |
| 自由交战 | 沿用自动索敌、追击与最小射程规避 | 会离开原来的阵位，需要留意侧翼与补给 |
| 原地警戒 | 只打实际射程、最小射程与视线均有效的目标，不自动追击或倒车 | 敌军可从射程外消耗；仍允许手动移动和返场，警戒圈不是穿墙探测 |
| 停火待命 | 停止射击和弹药拦截，普通移动仍可执行 | 继续承受伤害，不隐身、不减伤；手动攻击、攻击移动或巡逻恢复自由交战 |

- 仅陆军有火力的单位，包括士兵、坦克、火箭炮、防空、激光和反导。工程师、间谍、补给、运输及海空单位不新增这组控制，不改既有自主无人机规则。
- 切换警戒或停火会停止当前行军并清空待执行航点；已经安排的整备和登乘继续，但不再恢复原攻击计划。出厂过程仍先完成出口部署。
- 正常右键移动保留姿态。追加攻击移动不会提前覆盖当前姿态，到该段开始时恢复自由交战。
- 混编面板显示“混合编队”，只对符合条件的己方单位生效；新建单位默认自由交战，旧存档缺少字段也视为自由交战。
- 联机客户端发送命令，不先修改本地结果；服务端验证可控、存活、所有权与合法枚举，敌方和观战视图不发送该字段。

## 材质与界面

- 陆地装甲钢使用共享 256 像素颜色、法线、粗糙度贴图，增加消光涂层颗粒、擦痕与局部磨损反光；已有专用贴图不强行覆盖，不加几何零件和绘制批次。
- 保留海军独立灰色涂装、橡胶消光与金属差异。这只是材质细化，不是照片级模型重建。
- 选择面板提供图标分段开关、悬停说明、按下状态与批量切换；单选警戒显示射程参考圈，选中血条显示非默认姿态。
- 修复新按钮继承 HUD 鼠标穿透导致无法点击的问题；较长状态文字参与血条布局宽度计算，避免文字越出布局预算。

## 验收与未验收

- 自动测试 420 项通过，新增姿态实际开火／追击／遮挡／最小射程／阵营射程、停火拦截、保障流程、队列切换、存档校验、权威联机映射及隐私、贴图缓存测试。
- 生产构建通过。已有主包体积警告仍存在，没有用修改告警阈值隐藏。
- 浏览器通过真实鼠标选择、姿态按钮、右键攻击；警戒位置变化为 0，正常射击两发，停火期间弹药不变，手动攻击恢复自由交战。
- 实机确认坦克三个装甲网格使用新材质，画布非空、WebGL 错误为 0；1600×1000、1280×800 的按钮可点击且没有横向溢出，390 宽度仅做不越界回归。
- 用户手动／自动存档、普通荣誉和挑战档案未被测试覆盖。测试 fixture 没有用于保存或结算普通荣誉。
- 本轮不是双真人、六人长局或硬件性能验收。既有 240 单位计时受环境节流影响，不能作为流畅帧率承诺。

浏览器截图和原始记录位于本地 `releases/combat-stance-20261020/`，不随发行包宣称已经上线。

## 下一批顺序

1. 整理四类真实战斗标杆场景，先统一坦克、步兵与 F-22／AH-64 的比例、光照、机体材质和动作。
2. 补登陆或纵深侦察挑战，与固定任务的配兵和整备资金一起测试，不刷普通荣誉。
3. 做新装备双客户端与六方长局，记录确定硬件的性能曲线、弱网恢复和真人反制数据。
4. 通过以上验收后再确定 2.0 候选，统一更新代码、下载包、服务器及发布说明。
