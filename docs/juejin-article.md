# 惊呆了 我用 gpt6.1 开发了红警开源了

小时候玩红警，最熟悉的循环就是：采矿、造电厂、铺基地、攒一队坦克，然后发现对面已经把部队开到家门口了。

这次，我想借助 GPT 6.1 / Codex，把这种即时战略的乐趣做成一个自己的浏览器游戏。现在，一版能实际玩的《大国崛起》已经完成，我把源码、Blender 模型、素材记录和离线试玩包一起公开了。

先说明：标题里的“红警”指的是玩法灵感。**这是原创、非官方的红警风格 RTS，不是官方续作，也不是原版游戏资源的搬运。** 它目前是单机试玩项目，美术、AI 和平衡都还在继续完善。

**源码地址：[github.com/chencheng666/great-powers-rts](https://github.com/chencheng666/great-powers-rts)**

**试玩下载：[GitHub Releases](https://github.com/chencheng666/great-powers-rts/releases/latest)**

不想配置开发环境的朋友，下载 ZIP、完整解压，然后用电脑浏览器打开 `PLAY.html` 就能玩。模型、图片和配乐已经打进文件，游戏本体可以离线运行；中文实时播报是否支持离线，取决于设备的语音服务。

## 它现在能怎么玩

核心还是大家熟悉的基地经营与即时战斗，但我希望胜负不仅取决于“谁攒的坦克更多”。

目前有五个虚构阵营：华夏防卫、北境联邦、西陆同盟、东亚科技体、新月能源体。阵营有各自的特色加成、单位和战略技能，基础经济与生产规则保持一致。

一局游戏大致会经历这些阶段：

1. 采矿维持收入，建设电厂与生产设施。
2. 用侦察兵探路，让工程师争夺中立油井和雷达信标。
3. 按对方阵容选择坦克、防空、无人机、远程火力或舰艇。
4. 保护侦察与补给，利用桥头、海岸和地形组织进攻。
5. 按胜利规则摧毁敌方生产核心，或清除全部敌方建筑与单位。

矿石与宝石价值不同，油井提供持续收入，雷达信标提供情报而不是额外资金。供电不足会影响部分设施与生产，不是建筑造好后就可以完全不管后方。

生产也不是一个万能按钮：**兵营、战车工厂、兵工厂、空军基地与船坞各司其职，独立排队。** 玩家可以同时推进不同方向的建设，也必须考虑生产设施被摧毁后的影响。

四张地图分别是：

| 地图 | 主要体验 |
| --- | --- |
| 灰谷地带 | 陆战推进与基地经营 |
| 双桥裂谷 | 山体遮挡、桥头争夺与绕路 |
| 海峡前线 | 陆路桥梁与近岸舰艇配合 |
| 远洋战区 | 3520 × 2240 大地图，展开舰队与远程作战 |

目前支持“快速对战”和“全域歼灭”，以及三档单机 AI。还没有多人联机和完整剧情战役，这两点先说清楚，避免大家下载后期待落空。

## 加入现代装备，重点是形成克制

这次扩展，我没有只增加更大血量的坦克，而是加入了六种有不同职责的陆战装备。

| 单位 | 玩法定位 | 必须面对的限制 |
| --- | --- | --- |
| 巡飞弹发射车 | 根据侦察进行远程打击 | 弹药有限，巡飞弹能被拦截和干扰 |
| 电子干扰车 | 压制无人机与制导弹药 | 没有直接伤害，不能干扰无制导火箭 |
| 激光反无人机车 | 保护部队免受无人机与巡飞弹攻击 | 连续开火会过热，不能打坦克或高空战机 |
| 远程火箭炮 | 展开后进行区域打击 | 有最小射程，需要侦察、掩护和补给 |
| 装甲运输车 | 运送步兵与工程师 | 最多四名乘员，上下车受地形与空位限制 |
| 维修补给车 | 维持载具生命值与弹药 | 需要停驻，消耗资金与库存，不能无限续航 |

海战则新增了导弹驱逐舰、航空母舰与攻击潜艇。

驱逐舰能承担防空与反潜；航母通过可被击落的舰载机打击目标，飞机执行任务后返舰；潜艇能伏击舰艇，但需要声呐探测，也会在发射后短暂暴露。

所以，理想中的战斗链条是：**侦察提供目标，远程火力需要保护，无人机受到反制，补给决定持续作战能力。** 航母不是单舰无敌，火箭炮也不是全地图自动锁敌。

这些单位名称借用了现代装备类别，但射程、价格、伤害都是为游戏设计的数值，不对应真实武器性能。

## 和 AI 做游戏，更多时间花在迭代上

最早的版本可以玩，但我对画面并不满意：地图和单位偏 Q 版，建筑和地面的关系也不够自然。后来又遇到建筑像埋进地下、多个单位挤成一团、血条重叠等问题。

我的反馈很直接：画面需要更有科技感，建筑不能陷进地里，战车工厂和兵工厂要分开，还要有背景音乐、中文应答、全屏和可收起的右侧面板。

这些要求最后落实成了具体改动：

- 用 Three.js 重做战场渲染，车辆、步兵、飞机、舰艇采用三维几何。
- 调整建筑透明贴图的地表锚点，修正地基下陷与裁切。
- 增加炮塔转动、车辆转向、履带痕迹、受损烟雾与舰艇尾流。
- 按体型与移动层组织编队，加入近距离避让和出厂空位检查。
- 血条按优先级错位排列，拥挤区域避免全部标签互相覆盖。
- 接入原生全屏、侧栏折叠、音量控制与手机横竖屏布局。

![密集编队下的血条与单位排列验证](https://raw.githubusercontent.com/chencheng666/great-powers-rts/main/docs/images/unit-density.png)

上图是密集单位验证场景。它也提醒我：**模型好看只是第一步，玩家能不能选中、看清、指挥它们，同样重要。** 目前仍有拥挤与美术一致性问题，后续会继续优化。

![手机竖屏下的航母选中状态](https://raw.githubusercontent.com/chencheng666/great-powers-rts/main/docs/images/mobile-carrier.png)

手机支持触屏平移和缩放，不过 RTS 操作仍然更适合电脑；低端设备的性能和触屏体验也是接下来的改进方向。

## 技术栈没有很重

项目没有使用 React 或 Vue，主要是原生 JavaScript 加几个专注于各自职责的库。

| 技术 | 用途 |
| --- | --- |
| JavaScript ES Modules | 游戏规则、经济、AI、交互与界面 |
| Three.js | WebGL 战场、正交战术镜头、模型与动画 |
| PathFinding.js | A* 地面寻路，结合地图阻挡与桥梁通道 |
| Blender + Python | 程序化生成军事模型，导出 GLB |
| Vite | 开发服务、网页构建与资源处理 |
| Lucide | 指挥工具栏与操作图标 |
| Web Audio API | 配乐播放、合成战场音效、音量总线 |
| Speech Synthesis | 在玩家设备上实时播报中文指令 |
| Node.js 内置测试框架 | 规则、现代兵种与展示逻辑回归测试 |

架构上，`data.js` 定义单位、建筑和地图，`game.js` 负责模拟，`modern-combat.js` 放现代作战规则，`render.js` 负责画面，`main.js` 连接界面和操作。规则层与渲染层分开，便于不启动 WebGL 就测试经济和战斗行为。

## 美术素材怎么来的

主要是“AI 生成位图 + Blender 程序化模型”的组合。

地表、建筑、树木及独立兵工厂使用 AI 图像生成工具制作。提示词会明确相机角度、材质、透明背景和图集排布，相关记录保存在 `assets/asset-prompts.json`。

移动单位使用本地 Blender 生成。仓库中提供 34 类基础模型模板和 9 类现代单位模板，以及可编辑的 `.blend`、运行用的 `.glb` 和 Python 脚本。模板数量包含场景物件，并不等于可生产兵种数量。

目前的建筑和植被仍是透明图集，移动单位是真实三维模型，因此它是**混合渲染的策略游戏原型**，还不是所有建筑都能自由旋转查看的全三维写实作品。开场插画也不代表实际游戏画质，本文展示的都是运行截图。

背景音乐《前线序列》由程序编曲与合成，约 74 秒，可以循环；射击等音效由 Web Audio 合成。中文应答保留了 36 条台词，覆盖建造、生产、移动、攻击、警报与胜负通报。

开源前还检查了一次素材分发范围：早期本地系统语音录音不进入公开仓库，公开版改为玩家设备实时播报，避免把“本地能生成”误当成“可以随意公开分发”。[Apple 系统语音许可](https://www.apple.com/legal/sla/docs/macOSSequoia.pdf)包含相关限制。

项目代码采用 MIT 许可，素材来源与授权范围写在 `ASSETS.md`，第三方库保留各自授权。AI 生成素材不作独占性或商业使用无风险的保证，也没有使用原版红警的音乐、美术和配音。

## 放三段核心代码

完整实现都在仓库，这里只看三个设计点。

### 数据驱动的兵种配置

下面是 `src/data.js` 中火箭炮配置的节选，省略其他属性：

```js
rocket: {
  name: '远程火箭炮', cost: 880, hp: 230,
  range: 680, minRange: 180,
  ammo: 6, deployTime: 2,
  producer: 'armory', requires: 'lab',
  tags: ['vehicle', 'artillery']
}
```

射程、最小射程、弹药与展开时间一起决定战术定位。新增兵种不能只改模型和伤害，还要接入生产、探测、补给与 AI 选择。

### 同帧伤害先收集，再结算

`src/game.js` 中的更新流程节选如下，移动与其他更新省略：

```js
this.pendingHits = [];
this.collectingHits = true;
this.updateElectronicWarfare(dt);
this.updateProjectiles(dt);
for (const b of this.buildings)
  if (b.hp > 0) this.updateBuilding(b, dt);
for (const u of this.units)
  if (u.hp > 0 && !u.embarkedIn) this.updateUnit(u, dt);
this.collectingHits = false;
for (const hit of this.pendingHits) this.applyHit(hit);
```

这能减少同帧中“数组先遍历谁，谁就先把对方打死”的顺序偏差。不过它只是公平规则的一部分，并不意味着整个游戏已经实现严格确定性的联网同步。

### 看到地块，不等于发现潜艇

`canSeeEntity` 的开头检查如下，后续普通隐形单位逻辑省略：

```js
if (target.embarkedIn) return false;
if (target.owner === side) return true;
if (!this.isVisibleFor(side, target.x, target.y)) return false;
if (target.kind === 'unit' &&
    UNITS[target.type].tags.includes('submerged')) {
  return target.exposedUntil > this.time ||
    this.activeUnits(side).some(u =>
      UNITS[u.type].sonar &&
      distance(u, target) <= UNITS[u.type].sonar);
}
```

迷雾只是地块可见性，潜艇还需要声呐或开火暴露。渲染也必须遵守这个判断，否则单位虽然不能被攻击，却可能被模型或特效偷偷暴露位置。

## 公平与测试，不能只靠一句承诺

目前的公平约束包括镜像资源与出生布局、共同生产费用和单位规则、双方独立迷雾，以及不靠额外开局资金和属性加成提高 AI 难度。

本次开源整理后的自动测试共 **69 项通过**，覆盖经济、视野、地形、生产、弹药、干扰、拦截、运输、补给、舰载机、潜艇探测，以及血条与音量设置。开发过程中也做了桌面、移动视口、单位选取、全屏与离线包的浏览器检查。

但自动测试能证明的是这些规则按预期执行，**不能证明五阵营已经达到成熟竞技游戏的平衡**。这需要更多玩家使用不同战术进行真实对局。

## 源码运行和反馈

开发环境需要 Node.js 20.19+ 或 22.12+，浏览器需要 WebGL 2 与硬件加速。

```bash
git clone https://github.com/chencheng666/great-powers-rts.git
cd great-powers-rts
npm ci
npm run dev
```

`npm test` 运行测试，`npm run build` 构建网页，`npm run package:offline` 生成可分享的单文件试玩包。现成包在 [Releases](https://github.com/chencheng666/great-powers-rts/releases/latest)。

这个项目让我感受到，AI 辅助开发最有意思的部分，不是生成了多少行代码，而是能把一个想法快速做成可玩的东西，再通过具体反馈持续修改。人的工作也没有消失：玩法取舍、审美判断、测试验收和素材来源检查，都需要有人认真负责。

接下来，我想继续改进美术一致性、舰队与大编队寻路、AI 战术、低端设备性能，以及兵种克制与操作反馈。多人联机和地图编辑器也在开发清单里，但不是当前已完成的功能。
