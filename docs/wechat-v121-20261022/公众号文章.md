## 工厂的门，要和出车方向对上

以前有一个很明显的违和感：工厂画着大门，坦克却像从侧面冒出来。

这次把现代兵营、战车工厂、兵工厂的模型朝向、出口铺装和实际生产方向做了统一。双方镜像基地，以及六方战区的不同出生方向，都加了对应检查。

## 树、石头和地面，继续修细节

这次找到了岩石贴地的一个具体问题：迷雾刷新时，部分岩石会丢掉地形高度，重新落到固定高度上。

现在修正了这段逻辑。新建筑施工时，也会清理完整基座范围内的装饰物。地面部队经过时，附近容易盖住车辆的装饰树石会暂时隐藏，避免车体与装饰物互相穿插。

这里没有偷偷把装饰石头变成新的不可通行障碍，原有寻路规则和双方条件保持一致。

地图表现方面，常规地表做了适度提亮，增加植被色彩层次，删掉了一条缺乏作用的斜穿装饰公路。海岸增加了宽度有变化的沙质岸带和潮线。

![海岸、沙质岸带与地表表现，受控测试实机](https://www.daguojueqi.site/official/assets/v121-shoreline.jpg)

但也不夸大：海陆碰撞边界还没有重做成任意形状的自然海岸，整体地形仍需要继续打磨。

## 跑道终于参与出场了，但机场还没做完

本版让现代固定翼从跑道端部沿轴线驶出，再逐渐抬升。返场整备的目标改到了停机坪，避免直接指向机库中心。

这一步解决了部分“跑道只是摆设”的问题，但完整的机场系统还没完成。

接下来还要做更连贯的进离场航线、滑行与等待、多泊位调度，以及机场和飞机的比例精修。它们会继续开发，不会因为补了一个起飞表现，就写成“真实机场已经全部完成”。

## 这次重点解决：用 HTTPS 正常联机

以前的海外 IP 加端口入口，分享、访问和浏览器安全连接都不够方便。

现在前后端在上海国内服务器部署了一份，官网、游戏和下载都通过域名访问。网页使用 HTTPS，对战连接使用 WSS，不需要玩家关闭浏览器安全保护，也不用忽略证书警告。

双人和六方服务仍然分开，账户库与会话也分开，避免互相覆盖。

本轮已经做过实际公网验收：创建与加入房间、准备开局、同一战局内移动、连续航点、交战姿态、拒绝操控对手单位，以及六方淘汰和结算。自动回归测试共 **446 项通过**。

这不代表所有弱网、长局和硬件组合都验证完了。大家仍然可以把问题继续发给我，最好带上版本、地图、浏览器和复现步骤。

**双人联机：**两位玩家打开同一个在线入口，输入昵称，一人创建房间，另一人输入房间码加入，双方准备后由房主开始。

**六方实验：**六方互为对手，可真人与 AI 混合，不是 3v3，也还不是正式排位赛。两位真人试玩时请使用不同电脑或不同浏览器，避免同一会话互相顶掉。

## 技术上，还是把事情做扎实

延续之前 AI 辅助开发的方式，我继续用 Codex 配合代码检查、测试和实机验收。AI 能加快实现，但画面、规则和联机是否真的可用，最后仍然要打开游戏验证。

前端用 Vite 和 Three.js，负责三维战场、材质、阴影与交互。后端用 Node.js 和 WebSocket，负责房间与战斗规则；SQLite 保存游客身份和战绩。Nginx 负责域名、HTTPS 和安全连接转发。

网页会根据访问协议选择安全连接，核心逻辑很直观：

```js
const protocol = location.protocol === 'https:' ? 'wss:' : 'ws:';
const socket = new WebSocket(`${protocol}//${location.host}/battle-socket`);
```

这里展示的是双人入口的简化片段，六方入口使用独立路径。真正决定规则和结算的是服务端，不只靠页面上的按钮约束。

单机仍保留四关战术挑战、战斗复盘、装备图鉴、存档与荣誉档案。桌面版使用 Tauri，下载中心会按实际版本和构建结果列文件；未完成全部国产系统、显卡和处理器的实机验证，也没有把构建成功等同于兼容性认证。

## 哪些建议还没全部加入

游戏名称还在征集意见，本次没有直接改名。“明日”等建议我都愿意继续讨论，但会先把游戏本身做扎实。它是原创、虚构的现代与近未来题材 RTS，游戏中的胜负和参数不对应现实国家与装备的结论。

模型写实化也没有一口气完成。更自然的地形、建筑细节、材质分层和大军团性能，会继续一起验收。不能只看近景好看，再让正常对局变卡。

下一阶段，我会优先把机场运行、重点建筑与人物精修、挑战关卡和长局联机稳定性继续往前推进，再逐步走向 2.0。
